# 개발 순서 (TASKS)

각 Phase는 따로 지시한다. 아래 "지시 예시"를 Claude Code에 그대로 붙여 넣어 시작하면 된다. 각 Phase가 끝나면 완료 조건을 직접 확인한 뒤 다음으로 넘어간다.

---

## Phase 0 — 기반

- 프로젝트 생성, 스택 설정 (CLAUDE.md 기준)
- Supabase 연결, 마이그레이션 구조, RLS 기본 정책
- host → tenant 판별 미들웨어 (로컬에서는 `?tenant=slug` 또는 `slug.localhost`)
- 테마 토큰을 CSS 변수로 구성 (DESIGN.md의 토큰 표)
- 시드: 데모 학원 3개 (테마 A·B·C 각 1개)

**완료 조건**: 두 개의 데모 학원 주소로 접속하면 서로 다른 학원명과 색이 보인다. 한 학원 데이터가 다른 학원에서 조회되지 않는 것을 테스트로 확인.

> 지시 예시: "CLAUDE.md와 docs/SPEC.md를 읽고 Phase 0 계획을 세워줘. 구현 전에 테이블 목록과 RLS 정책 초안부터 보여줘."

---

## Phase 1 — 학원 홈페이지 (테마 A) + 상담 신청

- 섹션 컴포넌트를 테마 A 기준으로 구현, tenant_sections 순서대로 렌더
- S-01 ~ S-10 전체, 모바일은 M-01 ~ M-10과 M-NAV 시안 기준, 모바일 하단 고정 바
- 상담 폼 → leads, consents 저장, source 판별
- 메시지 발송은 목(mock) 어댑터로 콘솔 출력

**완료 조건**: 390px·1440px에서 S-01~S-10 확인. 상담 신청 시 DB에 lead와 동의 3종이 각각 저장된다. 필수 동의 없으면 제출 불가.

> 지시 예시: "Phase 1을 시작해. S-01 홈부터 design/academy/Main.dc.html과 MobileHome.dc.html을 참고해서 구현하고, 섹션은 SPEC 5장의 섹션 키로 분리해줘."

---

## Phase 2 — 관리자 로그인·대시보드·상담 관리

- A-00 로그인 (Supabase Auth), 역할별 접근 제어
- A-01 대시보드: 이번 달 방문·신청·테스트·등록, 오늘 연락할 상담
- A-02 상담 목록(상태 필터, 검색, 마스킹) + 상세 패널(상태 변경, 메모, 진행 기록)
- 관리자 공통 레이아웃 (사이드바)

**완료 조건**: 원장 계정은 자기 학원 상담만 본다. 상태를 바꾸면 lead_events에 기록되고 진행 기록에 즉시 보인다.

---

## Phase 3 — 카카오톡 자동화

- `lib/messaging/` 어댑터 (mock / 실제 대행사)
- 시나리오 6종 (SPEC 7장), 예약 발송 크론
- 광고성 규칙 서버 강제 (SPEC 8장), 문자 대체 발송
- A-03 시나리오 on/off·템플릿 편집·검수 상태, A-04 발송 내역·동의 현황

**완료 조건**: 마케팅 미동의자에게 광고성 발송을 시도하면 서버에서 거부된다. 21시 이후 예약된 광고성 메시지는 야간 미동의자에게 다음날 08시 이후로 밀린다. 이를 자동 테스트로 확인.

> 지시 예시: "Phase 3을 시작해. 실제 대행사 연동 전에 mock 어댑터와 규칙 테스트부터 작성하고, 규칙이 모두 통과하면 대행사 어댑터를 붙이자."

---

## Phase 4 — 콘텐츠 관리

- A-05 소식 (작성·예약·카톡 동시 발송), A-M 모바일 글쓰기
- A-06 후기·성적 사례 (동의 없으면 비공개 강제)
- A-07 반·시간표·잔여석·레벨테스트 시간, 매주 월요일 시간 확인 알림
- A-08 학원 정보·원장 소개·교습비 (변경 확인 모달, 이력), 플레이스 불일치 경고
- A-10 설정 (알림 번호, 연결 상태, 계정)

**완료 조건**: 관리자에서 수정한 내용이 홈페이지에 바로 반영된다. 동의 미확인 후기는 어떤 경로로도 공개 페이지에 나오지 않는다.

---

## Phase 5 — 테마 B·C

- 추가 섹션: results_stats, exam_system, curriculum, score_cases, teachers, day_flow, gallery, safety
- 테마별 토큰과 섹션 기본 순서 (SPEC 5장)
- 빈 데이터 섹션 자동 숨김
- 원장 강조색 변경

**완료 조건**: 데모 학원 3곳이 design/academy/Theme*.dc.html과 같은 구성으로 보인다. 섹션 컴포넌트 파일은 테마별로 복제되지 않았다.

---

## Phase 6 — 리포트·검색·분석

- GA4 연결, 전환 이벤트
- A-09 월간 리포트 (6개월 추이, 검색어, AI 검색 점검 수동 입력, 운영자 코멘트), PDF 내보내기, 매월 요약 카톡
- SEO 메타, JSON-LD, sitemap, robots

**완료 조건**: 데모 학원의 리포트가 실제 leads 데이터로 계산된다. 구조화 데이터가 검증 도구에서 오류 없이 읽힌다.

---

## Phase 7 — 첫등원 서비스 사이트 + 플랫폼 관리자

- F-01 ~ F-06a (design/marketing), 모바일 헤더는 햄버거 메뉴
- 무료 진단·베타 신청 저장, 운영자 알림, 신청 순번·예상 시작일
- 베타 기간 관리: 오픈일 기준 3개월 계산, 종료 2주 전 운영자 알림, 종료 후 30일 유지·비공개 전환
- P-01 ~ P-05 플랫폼 관리자 (design/screenshots/academy/P-*.png)
- 데모 페이지에서 데모 학원 3곳으로 연결

**완료 조건**: 운영자가 플랫폼 관리자에서 새 학원을 만들고 테마를 지정하면, 별도 개발 없이 그 학원 홈페이지가 열린다.
